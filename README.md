# CS-255 System Analysis and Design Portfolio

This repository contains selected portfolio artifacts from CS-255: System Analysis and Design. The materials demonstrate my ability to gather business requirements, analyze user needs, and design a system solution that aligns with client goals.

## Project Overview: DriverPass System

The DriverPass project involved designing a system for DriverPass, a company focused on helping students better prepare for their driving exams. The client requested a web-based system that would allow students to schedule driving lessons, access online instructional content, complete practice exams, and track their learning progress. The system also needed to support multiple user roles, including students, instructors, administrators, and an IT officer, while integrating with an external DMV database to ensure test content remained accurate and up to date.

## What I Did Well

One of my strongest contributions to this project was translating the client interview into clear, well-structured documentation. I carefully identified functional requirements, nonfunctional requirements, system constraints, and security considerations in the business requirements document. In the system design document, I created UML diagrams that clearly showed how users interact with the system and how system components communicate. These design artifacts helped bridge the gap between business needs and technical implementation.

## Opportunities for Improvement

If I were to revise one part of this work, I would expand the level of detail in some of the UML diagrams. While the diagrams accurately reflected the core system behavior, I would add more alternative flows and exception handling, such as scheduling conflicts or failed data synchronization with the DMV system. This would make the design more robust and closer to real-world scenarios.

## User Needs and System Design

I interpreted the user’s needs by closely reviewing the interview transcript and mapping specific client concerns directly to system features. For example, the client’s concern about outdated testing materials directly influenced the decision to integrate with the DMV database. Considering user needs is critical because a system that is technically sound but does not align with user expectations will ultimately fail. User-centered design ensures the system solves the right problems in a practical and usable way.

## Design Approach and Future Strategies

My approach to software design begins with fully understanding the problem before proposing solutions. I focus on identifying stakeholders, clarifying goals, and documenting requirements in clear language. I then use modeling techniques such as use case diagrams, activity diagrams, and sequence diagrams to validate my understanding before moving into detailed system design. In future projects, I plan to continue using these techniques while placing even more emphasis on iterative feedback and validation throughout the design process.
